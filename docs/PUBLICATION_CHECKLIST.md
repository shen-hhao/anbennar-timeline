# 手动发布检查表

首发标识为 `community-preview-20260923`，仓库为 [shen-hhao/anbennar-timeline](https://github.com/shen-hhao/anbennar-timeline)，站点为 [shen-hhao.github.io/anbennar-timeline](https://shen-hhao.github.io/anbennar-timeline/)。历史候选版本保持 `0.25.0`。仓库与分支式Pages发布已在维护者指令范围内；下面是执行核对流程，不是再次申请已经授予的授权。

## 每次发布前

1. 固定 `main` 候选提交与实际文件清单，核对准确范围；保留前值和上一份可用发布快照。不要将完整工作目录、研究原件、数据库或私人附件加入公开仓库。
2. 检查所有可下载内容，而不只看网页表面。来源定位使用公开URL、版本、来源ID及安全定位；保持原文、来源内容SHA、日期、身份和政治字段的约定保护。
3. 核 [第三方说明](../THIRD_PARTY_NOTICES.md) 与 [资产登记](ASSET_RIGHTS.md)。保持团队、作者及适用上游归属；本次不赋予项目整体统一再分发许可证，不给第三方内容套MIT。新的权利方订正或移除请求须纳入处理。
4. 在公开副本目录执行 `npm run check`、`npm test`，按影响范围打开本地页面。核 `/anbennar-timeline/` 项目子路径、首次加载、年份切换、国家详情、来源与反馈入口；结果绑定真实输入，保留失败和未执行项。
5. 核37项阶段限定、19处1820有界续接及隐厦未纳入等说明仍准确。关闭条纹不取消限定，程序通过不提升历史确定性。
6. 确认仓库不含 `.github/workflows/`，没有自定义自动检查、自动部署或定时反馈任务。PR审查附本机实测结果，不填写不存在的CI通过状态。

## 发布分支与在线核对

1. `main` 保存 `dist/`、指南、脚本与测试，更新它不直接上线。按维护者已明确授权的发布范围，准备对应 `gh-pages` 快照。
2. 在干净的Git检出运行 `node scripts/prepare-pages.mjs`，制作全新本地暂存目录。它复制 `dist/` 内部内容、加入 `.nojekyll`，并生成绑定来源提交和文件SHA的 `publication.json`；不提交、不推送、不配置远端。根目录应直接可见 `index.html`，不套 `dist/`，也不混入研究原件或数据库。
3. Pages从 `gh-pages` 的 `/ (root)` 发布，使用默认 `github.io` 地址。平台内建部署是已选方案的一部分，没有自定义工作流文件；`.nojekyll` 不取消平台部署。
4. 按对话授权推送发布分支，记录来源提交与发布提交。此推送就是上线操作，不由普通 `main` 提交或网友Issue触发。
5. 部署完成后核实际URL、版本和关键文件，不把推送成功或平台完成状态当作用户页面正确的证明。`release.json` 记录候选标识、日期与范围；本地暂存工具生成的 `publication.json` 绑定来源提交和静态文件SHA；实际发布提交与部署时间以Git/Pages记录为准。不在文档中填会引起自引用的SHA占位。
6. 必要回退按维护者指令使用上一份已验证快照，保留原因、前后提交与检查结果。上线不改变历史方案的来源等级和既有未决项。

本表描述核对要求，不替代实际执行结果。后续反馈仅在维护者发起的对话内读取和处理，见 [手动反馈流程](FEEDBACK_WORKFLOW.md)。
